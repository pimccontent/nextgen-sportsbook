1. Requirements / DNS / ports

  • Linux VPS: Ubuntu 22.04 or 24.04, root SSH
  • 2 GB RAM minimum (4 GB recommended for first image build)
  • Domain you control + DNS panel access
  • Email for Let’s Encrypt certificates
  • Not for classic shared hosting / cPanel PHP-only

DNS (path layout — recommended)

HostnameTypeTarget
YOUR_DOMAINAVPS public IP
admin.YOUR_DOMAINAVPS public IP
Cloudflare: Use DNS only (grey cloud) for apex and admin. until certificates are issued. Proxied (orange) DNS often breaks Let’s Encrypt HTTP-01 until Caddy is healthy.

Ports (Azure NSG / cloud firewall)

PortPurpose
22SSH
80HTTP → ACME + redirect to HTTPS
443HTTPS (Caddy)

On Azure, open these on the Network Security Group attached to the VM/NIC, not only UFW inside the guest.

3. Step-by-step installation

  1. Create the VPS
    Provision Ubuntu 22.04/24.04. Note the public IPv4. Confirm root SSH (or sudo).
  2. Add DNS records first
    Create the two A records above. Wait for propagation. Certificates fail if DNS is wrong.
  3. (Optional on 1–2 GB VPS) Add swap 
    sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
  4. SSH into the VPS 
    ssh root@YOUR_VPS_IP
  5. Guided wizard (smoothest) 
    curl -fsSL https://raw.githubusercontent.com/pimccontent/nextgen-sportsbook/main/scripts/install-vps.sh | bash -s -- --wizard --install-docker
    Prompts for domain, Let’s Encrypt email, layout (path recommended), and optional prebuilt images. Then checks DNS, installs Docker, opens ports 22 / 80 / 443, and starts the stack.
  6. Non-interactive one-liner 
    curl -fsSL https://raw.githubusercontent.com/pimccontent/nextgen-sportsbook/main/scripts/install-vps.sh | bash -s -- --domain=YOUR_DOMAIN --email=YOU@EMAIL.com --install-docker
  7. Wait for the first build
    First run can take several minutes. When finished, Customer / Agent / Admin / API URLs print in the terminal.

What the installer does

  1. Installs packages (curl, git, ufw, …)
  2. Installs Docker Engine + Compose v2
  3. Clones the repo into ~/nextgen-sportsbook
  4. Opens firewall ports 22 / 80 / 443
  5. Checks DNS for apex + admin.
  6. Writes .env.vps with HTTPS URLs and CORS
  7. Starts Postgres, Redis, API, Customer, Admin, Agent, and Caddy
  8. Caddy obtains Let’s Encrypt certificates for the two hostnames

5. Updates / troubleshooting

Update the stack

cd ~/nextgen-sportsbook
bash scripts/update-vps.sh
# optional:
bash scripts/update-vps.sh --pull-git
bash scripts/update-vps.sh --build

Useful commands

bash scripts/check-dns.sh --domain=YOUR_DOMAIN

docker compose -f infrastructure/docker-compose.vps.yml --env-file .env.vps --profile https ps

docker compose -f infrastructure/docker-compose.vps.yml --env-file .env.vps logs -f api
docker compose -f infrastructure/docker-compose.vps.yml --env-file .env.vps logs -f caddy

If you change public URLs / Next.js env

docker compose -f infrastructure/docker-compose.vps.yml --env-file .env.vps --profile https up -d --build customer admin agent

Common issues

SymptomFix
Certificate / HTTPS fails Confirm A records; Cloudflare grey-cloud; ports 80/443 open on cloud NSG + UFW; re-run update after DNS is correct.
Admin login fails / 500 Check API logs; Redis/Postgres must be up; entrypoint maps DB/Redis host ports correctly inside Compose.
Blank admin / wrong API host Admin resolves API from admin. → apex /api/v1. Rebuild frontends if NEXT_PUBLIC_* was wrong at build time.
OOM during first build Add 2G swap; prefer 4 GB RAM; or use prebuilt images (USE_PREBUILT_IMAGES=1).

6. Admin guide — overview

All business rules live on the Laravel API. Frontends are clients. After install, configure the product in this order:

  1. Operations — environment (sandbox/live), maintenance
  2. Branding — name, colors, logo, favicon
  3. Payments — Paystack keys (write-only secrets)
  4. Sports data — provider + auto-publish
  5. Fixtures — sync → draft → publish; edit locks provider updates
  6. Promotions / Commissions — % and flat GHS
  7. Staff — least-privilege modules
  8. Live chat — support widget
  9. Domain & deploy — read-only topology + update command

UI tips use a small i info icon — hover or focus for guidance instead of long page essays.

7. Operations & Branding

Operations

  • Sandbox (default): mock/test money paths allowed; demo deposits may be available.
  • Live: confirm by typing LIVE; updates payment mode banners. Does not alone enable Paystack HTTP — complete go-live checklist separately.
  • Maintenance: blocks Customer and Agent; Admin stays up.

Branding

  • Site name, day/night color palettes, logo/favicon uploads (stored on API /storage/…).
  • Customer messages: lobby popup/toast IDs — bump ID after copy changes so returning visitors see updates.
  • Hero banners managed under Banners.

8. Payments

  • Provider defaults to Paystack-compatible adapters.
  • Secrets are write-only in Admin (hint shown when configured; plaintext never returned).
  • Live deposits credit only via signed webhooks — never trust frontend “payment success” alone.
  • Manual deposit manager (sandbox/test) lives under Admin → Deposits.
  • Withdrawals are cash-only; bonus wallet is segregated.

9. Sports data & fixtures workflow

Sports data settings

  • Free providers: mock, embedded_world, openligadb (no key), thesportsdb (demo key 123, rate-limited), optional football-data.org free token.
  • Auto-publish imports defaults to off. Sync creates Draft fixtures until you publish. Turn on only if you want unlocked imports visible to customers immediately.
  • Default 1X2 odds apply to newly created selections only.

Fixtures workflow

  1. Sync (Admin → Fixtures → Sync) pulls provider catalogue into the database.
  2. New/unlocked rows arrive as Draft unless auto-publish is on.
  3. Publish (single or bulk) makes fixtures visible — publishing alone does not lock the fixture.
  4. Unlocked fixtures keep accepting provider updates on sync/refresh (kickoff, status, scores when the provider returns them).
  5. Locked (admin_locked) happens when an admin edits controlling data: schedule, live clock/scores/result, odds, markets, match script, or custom create. Provider sync then skips overwrites.
  6. Suspend hides from customers without deleting; sync will not un-suspend.
Live depth: Scheduled fixtures:live-sync polls unlocked fixtures that have real provider event ids (tsdb:, oldb:, fd:) for status, scores, and minute/period when the API returns them. Locked fixtures (admin_locked) are never overwritten — admin edits and match scripts remain source of truth. Synthetic catalogue rows (emb: / mock: / custom:) are not auto-marked LIVE by the local clock; publish provider-backed fixtures or arm a script for controlled live play. TheSportsDB free demo key supports event lookup; premium keys can also use V2 soccer livescores.

Match scripts

On a fixture detail page: set durations / planned scores → Save & arm. Arming locks the fixture and auto-starts at kickoff for sandbox clocks.

10. Promotions & commissions (%)

  • UI shows simple percent (enter 10 for 10%) and flat GHS amounts.
  • Storage remains integer basis points / minor units (10% ↔ 1000 bps; GHS ↔ pesewas ×100).
  • Backend math unchanged (/ 10000 for bps).
  • Deposit/win bonuses credit the segregated bonus wallet; winnings from bonus-funded stakes settle to cash.
  • Agent portal commissions list shows rates as 2%, not raw bps.

11. Staff permissions, support chat, domain

Staff

  • Super Admin has full access; create limited staff under Admin → Staff with explicit modules (dashboard, fixtures, customers, deposits, support, …).
  • Least privilege: only enable modules each operator needs.

Live support

  • Enable under Settings → Live chat (greeting, hours, canned replies, enter-to-send).
  • Customer /support + Admin → Live support inbox; attachments, emoji, unread bell.

Domain & deploy

  • Read-only panel of current VPS topology and URLs.
  • Does not push production by itself — rebuild on the server with:
cd ~/nextgen-sportsbook
bash scripts/update-vps.sh --pull-git --build
